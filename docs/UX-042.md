# KINOSIS 0.4.2 — UX Cohesion Notes

The central problem in 0.4.1 was not missing features. It was that each feature felt like a separate tool. 0.4.2 defines one product grammar.

## 1. One destination = one user job

- **Discover:** What should I watch?
- **Arthouse:** What should I explore as cinema?
- **Library:** What have I saved, and how do I manage it?
- **My:** What has my film life looked like?
- **Detail:** One film's public information + my relationship with it.

Search is a global action. Admin is an internal tool, not a public top-level destination.

## 2. Repeated UI grammar

The site now limits repeated visual primitives:
- Poster Card
- Editorial Card
- Library Row
- Stat Card
- Dialog / Toast

Primary, secondary, and ghost actions share the same hierarchy everywhere.

## 3. Progressive disclosure

Poster cards answer only two time-sensitive questions:
- Is it in theatres?
- Which subscription services can I watch it on?

Detailed provider types (rent/buy/free) live on the film page.

## 4. Content-first Discover

Discover no longer asks users to choose a sub-mode before seeing films. It is a single feed composed of a small number of high-value shelves.

## 5. Editorial identity

TMDB arrays alone make a product feel like an API viewer. Curations provide a visible KINOSIS editorial voice. Only one main curation is surfaced in Discover; Arthouse can carry deeper editorial programming.

## 6. Library density

Discover optimizes recognition and attraction. Library optimizes retrieval and management. Library therefore uses smaller cards, denser layouts, persistent filtering, and a list view.

## 7. My as autobiographical space

My is not another library. It summarizes the user's relationship with film: recent viewing, reviews, calendar, stats, subscriptions, account status.

## 8. Arthouse

Arthouse is not a visual theme. It is an editorial/content destination. The classifier only generates candidate films; curated programming can override or refine it.
